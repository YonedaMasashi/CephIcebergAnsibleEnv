
## 構成の考え方

| 層 | 配置 | 理由 |
|---|---|---|
| **Ceph**（Tentacle v20） | ホストに cephadm で構築し、RGW で S3 互換 API を提供 | Ceph は compose 向きではありません。cephadm で単一ホスト構築するのが現行の標準的な方法です |
| **PostgreSQL / Hive Metastore / Trino** | docker compose | ステートレス寄りで、作り直しが簡単 |
| **PyIceberg** | ホストの venv `/opt/pyiceberg` | クライアントライブラリなのでコンテナにする必要がありません |
| **Iceberg** | （サーバーなし） | テーブルフォーマットなので、Trino と PyIceberg が同じ HMS と同じバケット（`s3a://warehouse/`）を共有することで成り立ちます |

なお、コンテナランタイムは podman を使用します

## 事前準備（Ansible, docker で自動化できない設定）
- VM の設定
    - 推奨スペック: vCPU 4、メモリ 16GB。
- ストレージの設定
    - (VM 停止中に以下を実行してください)
    - VM の「設定」→「ストレージ」を開きます
    - 「コントローラー: SATA」を選び、右側の「ハードディスクを追加」アイコンを押します。
    - 「作成」→「VDI」→「可変サイズ」→ サイズ 20GB →「完了」と進み、作ったディスクを選んで「選択」を押します。
    - 手順 3〜4 をあと 2 回繰り返します（合計 3 本）。
    - VM を起動して ```lsblk``` を実行し、次のように sdb、sdc、sdd がパーティションなし・マウントなしで表示されれば OK です。
        ```
        sda      8:0    0   50G  0 disk
        ├─sda1 ...
        ...
        sdb      8:16   0   20G  0 disk
        sdc      8:32   0   20G  0 disk
        sdd      8:48   0   20G  0 disk
        sr0     11:0    1 1024M  0 rom
        ```
- NIC の設定
    - NIC は「NAT」と「ホストオンリー」の 2 枚構成にし、ホストオンリー側に固定 IP（例: 192.168.56.10）を設定します。以下の手順を実行してください
    - ホストオンリーネットワークを確認する（VirtualBox）
        1. VM停止中に、VirtualBox マネージャーで「ファイル」→「ツール」→「ネットワークマネージャー」を開きます。
        2. 「ホストオンリーネットワーク」タブに `VirtualBox Host-Only Ethernet Adapter` があることを確認します。なければ「作成」を押します。
        3. その行を選び、下の設定を確認します。

            | タブ | 項目 | 値（既定） |
            |---|---|---|
            | アダプター | IPv4 アドレス / マスク | `192.168.56.1` / `255.255.255.0` |
            | DHCP サーバー | 範囲 | `192.168.56.101`〜`.254` 程度 |

            `192.168.56.1` は Windows 側の IP です。VM に振る `192.168.56.10` は DHCP の範囲外なので、DHCP は有効のままで構いません。

    - VM に NIC を 2 枚設定する（VM は停止状態で）
        - VM をシャットダウンし、VM の「設定」→「ネットワーク」で次のようにします。

            | | 割り当て | 名前 | 用途 |
            |---|---|---|---|
            | アダプター 1 | NAT | - | インターネット（dnf、イメージ取得） |
            | アダプター 2 | ホストオンリーアダプター | `VirtualBox Host-Only Ethernet Adapter` | Windows から VM への接続（SSH、Trino UI など） |
        - アダプター 2 は「ネットワークアダプターを有効化」にチェックを入れます。設定したら VM を起動します。

    - 固定 IP を設定する（Rocky Linux）
        1. NIC 名を確認する
            ```bash
            ip -br addr
            ```
            例えば次のように表示されます。
            ```
            lo        UNKNOWN  127.0.0.1/8
            enp0s3    UP       10.0.2.15/24          ← アダプター1（NAT）
            enp0s8    UP       192.168.56.101/24     ← アダプター2（ホストオンリー、今は DHCP）
            ```
            通常、NAT 側は `enp0s3`、ホストオンリー側は `enp0s8` です。以下は `enp0s8` として書くので、違う名前ならその名前に置き換えてください。

        2. 既存の接続設定を確認する
            ```bash
            nmcli -f NAME,DEVICE con show
            ```
            `enp0s8` に紐づく接続（名前は `enp0s8` や `有線接続 2` など）があれば、名前を控えておきます。

        3. 固定 IP の接続を作る
            ```bash
            # 既存の自動接続があれば削除（名前は 3-2 で見たもの。名前が日本語ならそのまま引用符で囲む）
            sudo nmcli con delete "有線接続 2"

            # 固定 IP の接続を新規作成
            sudo nmcli con add type ethernet ifname enp0s8 con-name hostonly \
            ipv4.method manual \
            ipv4.addresses 192.168.56.10/24 \
            ipv4.never-default yes \
            ipv6.method disabled \
            connection.autoconnect yes

            sudo nmcli con up hostonly
            ```
            ポイントは 2 つです。
            - **ゲートウェイは設定しない**: ホストオンリー側に既定ゲートウェイを付けると、インターネット向けの通信がそちらに流れて外に出られなくなります。`ipv4.never-default yes` はその保険です。
            - **DNS も NAT 側に任せる**: ホストオンリー側には設定不要です。

    - 確認
        - VM 側で確認します。
            ```bash
            ip -br addr show enp0s8      # 192.168.56.10/24 になっているか
            ip route                     # default が enp0s3（10.0.2.2 経由）だけになっているか
            ping -c 2 192.168.56.1       # Windows に届くか
            ping -c 2 8.8.8.8            # インターネットに出られるか
            ```
        - Windows 側（PowerShell）でも確認します。
            ```powershell
            ping 192.168.56.10
            ssh your_user@192.168.56.10
            ```
            SSH で入れれば完了です。以降は Windows のターミナルから SSH で操作できるので、前の回答の `scp` もそのまま使えます。

            **補足**: Windows からの `ping` は通るのに VM から `192.168.56.1` への `ping` だけが通らない場合は、Windows ファイアウォールが ICMP を受け付けていないだけです。構築作業には影響しません。
- ホスト名を変更
    - プロンプトが [（ユーザー名）@localhost ...] となっている場合次のような問題が起きるので、playbook を流す前に変更してください。
        - cephadm は、ホスト名でクラスタ内のノードを識別します。localhost だと正しく動きません。
        - playbook が /etc/hosts に 192.168.56.10 localhost を追記してしまい、名前解決がおかしくなります。
    - ホスト名を変更するコマンド
        ```
        sudo hostnamectl set-hostname rocky10
        ```
    - 変更したら、一度ログアウトして入り直すとプロンプトにも反映されます。名前は rocky10 以外でも構いませんが、英小文字・数字・ハイフンだけにしてください。

## 実行手順（概要）

1. **zipの解凍**: dataplatform-ansible-podman.zip を解凍する
2. **ファイルを転送**: PowerShell で `scp -r .\dataplatform-ansible user@192.168.56.10:~/`
3. **パーミッション設定**: 書き込み権限を所有者だけに絞ります。(展開したフォルダが「誰でも書き込める（world writable）」パーミッションになっているため、Ansible がセキュリティ上の理由で ansible.cfg を読み込めないため)
    ```
    chmod -R go-w ~/dataplatform-ansible-podman
    ```
2. **Ansible をインストール**: VM 上で `sudo dnf install -y ansible-core`
3. **変数を編集**: `group_vars/all.yml` の `node_ip` と `osd_devices` を環境に合わせます。`osd_devices` は `lsblk` で確認してください。パスワード類もここで変更します。
4. **実行**: `ansible-playbook site.yml -K`。所要時間は 20〜40 分程度です。終わったら一度ログインし直してください（docker グループの反映のため）。
5. **確認**:
   - Ceph: `sudo cephadm shell -- ceph -s`
   - Trino: `sudo podman exec -i trino trino < ~/dataplatform-samples/sample.sql`
   - PyIceberg: `/opt/pyiceberg/bin/python ~/dataplatform-samples/pyiceberg_sample.py`
   - PyIceberg で作ったテーブルを Trino から SELECT できれば、**同じ Iceberg テーブルを共有できている**ことになります。

## 注意点

- **バージョン固定**: Hive Metastore は `apache/hive:4.0.1` に固定しています。同梱の Hadoop 3.3.6 に合わせて、S3A 用の `hadoop-aws` と AWS SDK の JAR を Maven Central から取得してマウントしています。Hive のバージョンを上げる場合は、この 2 つの JAR も合わせて変えてください。
- **RGW のポート**: RGW は Trino の 8080 と重ならないよう 7480 にしています。
- **ディスクが 1 本の場合**: レプリカ数 1 を自動で設定し、HEALTH_OK になるようにしています（冗長性はありません）。
- **Ceph RGW との互換性**: Trino が正式に互換テストしている S3 互換ストレージは AWS S3 と MinIO だけで、Ceph RGW は対象外です。書き込みでエラーが出た場合の回避策（`s3.exclusive-create=false`）を README のトラブルシューティングに書いてあります。

検証が進んだら、Spark の追加や HMS から Iceberg REST カタログへの切り替えとの比較などにも広げられます。
